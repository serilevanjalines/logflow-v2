# Experiment 0 — Baseline Performance

## Objective

Establish a baseline for LogFlow under a small concurrent workload.

The experiment measures how quickly LogFlow can accept HTTP log-ingestion requests while using:

- Redis as the log queue
- 3 LogFlow worker goroutines
- PostgreSQL/Supabase for persistence

This is a baseline experiment, not a maximum-capacity test.

## Configuration

| Parameter | Value |
|---|---:|
| Total HTTP requests | 100 |
| Benchmark workers | 5 |
| Requests per benchmark worker | 20 |
| LogFlow workers | 3 |
| Redis | Enabled |
| PostgreSQL | Enabled |
| Request type | `POST /logs` |

## Workload

Five benchmark goroutines were used to generate the workload concurrently.

Each benchmark worker sent 20 HTTP requests:

```text
5 benchmark workers × 20 requests = 100 requests
```

The benchmark communicated with LogFlow through its HTTP API rather than calling internal functions directly.

## Result

- Total requests: **100**
- Successful requests: **100**
- PostgreSQL rows persisted: **100**
- Total benchmark duration: **90.14 ms**
- Observed HTTP acceptance throughput: **1109.35 requests/sec**

## Log Timestamp Observation

The `timestamp` stored in the `logs` table is generated by LogFlow when the log enters the system.

Therefore, the first-to-last timestamp difference of approximately **85.72 ms** represents the spread of ingestion timestamps for the benchmark requests.

It does **not** represent PostgreSQL insertion time.

## Interpretation

All 100 requests were successfully accepted and all 100 benchmark logs were eventually persisted to PostgreSQL.

The baseline workload completed in approximately 90 ms, producing an observed throughput of approximately 1109 requests/sec.

This result should not be interpreted as the maximum capacity of LogFlow because the workload contained only 100 requests.

Future experiments will increase the workload while controlling other variables so that changes in system behavior can be observed.

## Next Experiment

Increase the number of requests while keeping the LogFlow configuration unchanged.

The goal is to determine how the system behaves as the workload increases and whether throughput, failures, queueing, or processing time begin to change.
